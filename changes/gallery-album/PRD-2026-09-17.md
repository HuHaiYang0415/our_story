# 相纸页 PRD：流光相册盒 · 我们的生活邮册

> 已被 [2026-09-18 单屏环绕邮册 PRD](PRD-2026-09-18.md) 替代。本文中的纵向列表/说明滚动、多层标签和地图暂缓决定已撤销，不可继续作为新版本执行依据。保留本文用于参考研究与历史追溯。

## 0. 文档定位与决策摘要

**产品主张：把一起过的日子，寄给未来的我们。**

将相纸页设计为一本持续生长的生活邮册：每段回忆是一张有封面、有日期、有短记的收藏票，打开后是一组照片。它能容纳一次旅行、一场约会、一顿晚饭、一个普通周末，也能收下一张不想忘记的照片。

本版的设计组合是：**纸物化的回忆封面 + 按时间整理的收藏页 + 可选地点索引 + 原比例大图观看。**

### 已确认的需求

- 相册内容包括旅行、约会与日常照片，不以旅游为唯一场景。
- 延续此前确认的“按一次经历成组”，本次将“经历”扩展到日常片段与明确命名的生活合集。
- 保留日期、地点记录能力；未来希望上传，本版仍由维护者添加文件资源和内容清单。
- 页面遵循情侣手作感、温馨治愈的项目风格。
- 本轮交付 PRD，不编写页面代码。

### 本 PRD 的建议决策

- 默认入口是按时间排列的回忆票；每张票进入一组照片。
- **相册为主体，地点为辅助维度。** 无城市、无坐标、无完整日期的照片都能被收录。
- 日常、约会、旅行和纪念日共用一套内容模型与浏览流程，通过可选标签辅助筛选。
- 纸张、票根缺口与邮戳用于外框和题签；照片本身保持原始比例与色彩。
- P0 提供地点文字索引；可交互地图列入 P1。地图优先级为当前建议，尚未得到用户单独确认，可在评审中调整。

本文件接替 [2026-09-15 初版方案](design-plan-2026-09-15.md) 作为相册下一版的需求提案。它不替代 [SCOPE.md](../../SCOPE.md) 对实施、基线和发布的授权，也不将目标需求写成当前已实现能力。

## 1. 背景与当前状态

### 1.1 要解决的问题

1. 照片需要保留“那天发生了什么”，不能只有文件和缩略图。
2. 只按旅行或城市组织，会使做饭、宅家、散步、宠物、随手拍等日常内容没有自然位置。
3. 单纯罗列照片容易失去纪念物的温度；装饰和叠放过多，又会影响找图和观看。
4. 当前没有服务端存储，页面必须先通过静态资源真实可用，同时为未来上传保留清晰的数据边界。

### 1.2 2026-09-17 源码核对结果

- 入口仍为 `#photos`，页面标题仍为“流光相册盒”。
- [PolaroidGallery.tsx](../../Cabinet/src/pages/gallery/PolaroidGallery.tsx) 已存在索引、相册内页、大图、年份筛选、分批展示和图片失败处理的基础代码，不再是初版调研时的装修占位页。
- [内容领域模型](../../Cabinet/src/domain/content.ts) 已包含相册开始/结束日期、日期精度、地点、封面，以及照片级注记、日期、地点和宽幅排版信息。
- [本地 adapter](../../Cabinet/src/data/localContentRepository.ts) 的相册集合仍为空，尚无实际相册数据；没有上传或后端存储能力。
- 上述是源码事实，本轮没有对现有相册完成浏览器实测，不据此宣称当前交互已通过验收。

### 1.3 项目边界

沿用 [PRODUCT.md](../../PRODUCT.md)、[DESIGN.md](../../DESIGN.md)、[AGENTS.md](../../AGENTS.md)、[内容契约](../../docs/CONTENT-CONTRACT.md) 与 [资源加载规范](../../Cabinet/docs/RESOURCE-LOADING-GUIDELINES.md)。

本 PRD 的产品范围只覆盖相纸页及必要的内容读取集成。展柜、信箱、相恋时光和节日页不随相册调整而重新设计。用户要求的“温馨治愈”通过内容和材料表达，不新增一套与全站冲突的视觉品牌。

## 2. 参考研究与转化结论

本轮已逐张查看用户参考目录中的 11 张 WebP 图，并读取 Map for Love 的 README 及相关源码片段。参考中的按钮、安装指南和管理流程只是研究材料，不构成操作授权。

### 2.1 本地邮票/票根相册参考

来源：用户提供的参考图目录。截图显示产品名 PicSlicer，视觉主体是横向票根、竖向相纸和收藏页。仅凭截图不能验证其真实手势、动效、保存或下载行为。

**观察 A：照片被整理成可收藏的纸物。**

- `imgi_14`、`imgi_18`：首页使用横票堆叠、竖片扇形展开，分别展示日间和夜间外观。
- `imgi_19`—`imgi_22`：横票以照片、侧边信息区、虚线、缺口形成完整物件。
- `imgi_23`、`imgi_24`：竖片使用留白、日期和照片形成安静的阅读面。

转化：我们的每组回忆拥有一张“回忆票”。借用纸边、题签、日期印记，首屏精选允许轻微叠放；正式列表保持可读排列。

**观察 B：一句具体的话让照片获得记忆。**

- `imgi_14`、`imgi_15`、`imgi_17` 可见照片上的短句注记，内容涉及天气、看到的东西和当时感受。

转化：每组回忆提供可选“一句话”，例如“面有一点咸，但两个人都吃完了”。这类生活细节优先于自动生成的抒情文案；正式文字由用户提供。我们的注记放在纸面留白，不压住照片主体。

**观察 C：收藏页同时提供时间与分类索引。**

- `imgi_17` 可见城市分类、年份/月度索引和横竖混排的收藏票。
- `imgi_15` 可见单票查看与底部缩略序列；`imgi_16` 可见横竖模板选择。

转化：采用生活标签、年月与地点辅助找回；大图可选用缩略序列。横竖模板由素材和布局规则决定，本版不提供制作器。

**不照搬的部分：**大面积全大写城市名、票号、探索城市统计、重玻璃底栏、照片上覆盖大标题、整个列表堆叠遮挡。我们的主标题是回忆名称，不是城市名称。

### 2.2 Map for Love 开源项目

来源：[项目仓库](https://github.com/WyankinzZ/map-for-love)。核对版本为 `3121878dc4ffc71b22353f5afe85f4040d21ef27`，调研日期 2026-09-17；未安装或运行该项目。

**观察 A：同一批回忆可按城市或时间浏览。**

[MemoryArchive.tsx](https://github.com/WyankinzZ/map-for-love/blob/3121878dc4ffc71b22353f5afe85f4040d21ef27/components/MemoryArchive.tsx) 中可见城市/时间线切换、城市/日期/文字搜索、心情筛选和大图状态。

转化：时间和地点应是同一份相册内容的不同入口，不能复制为两份数据。本版以时间为主，地点次之；不直接复制其城市优先的默认设置。

**观察 B：地点连接到具体故事。**

[CityPanel.tsx](https://github.com/WyankinzZ/map-for-love/blob/3121878dc4ffc71b22353f5afe85f4040d21ef27/components/province/CityPanel.tsx) 中可见按 `memory` 参数选择特定回忆，以及日期、文字、多张照片、封面和城市历史回忆的关联。

转化：点击一个地点，应能找到在那里发生的多段回忆。同一城市的多次约会不合并成一张城市卡后丢失区别；从相纸或地点进入，最终打开同一册。

**观察 C：大图从复杂地图布局中独立出来。**

[Lightbox.tsx](https://github.com/WyankinzZ/map-for-love/blob/3121878dc4ffc71b22353f5afe85f4040d21ef27/components/shared/Lightbox.tsx) 使用顶层 Portal，并实现关闭、方向键切换和触摸相关状态。

转化：我们的大图也应独立于纸张装饰与舞台变换，完整显示照片；键盘、触控、焦点和返回作为明确验收项，不因参考有实现就假定可直接复用。

**观察 D：时间线用路径和照片串起经历。**

[TimelineOverlay.tsx](https://github.com/WyankinzZ/map-for-love/blob/3121878dc4ffc71b22353f5afe85f4040d21ef27/components/TimelineOverlay.tsx) 可见轨迹点、路径、分阶段显示和照片叠层；README 还描述了电影式旅行回看。

转化：保留“照片带回当时”的情绪目标；自动播放旅行轨迹不进入本版。未来如果做路径回看，只对用户明确编排的同一次旅行开放，不能把日常照片自动连成实际行程。

**不照搬的部分：**城市必填、地图作为唯一入口、白粉蓝现代面板、心情发光点、天气/纪念日小组件、管理后台和桌面/安卓存储机制。只研究设计机制，不迁入其 Next.js/Electron 架构或上传实现。

### 2.3 综合设计判断

三个候选方向：

1. **生活邮册，推荐：**回忆票作为入口，时间为主序，地点为辅助；兼容日常与旅行，保持收藏感和可查找性。
2. **地图与旅行票根主导：**地点记忆强，但无定位和宅家内容会被边缘化。
3. **自由拼贴桌面：**开场手作感强，但相册增多、手机操作与键盘顺序较难维持。

本 PRD 采用第一种。把第二种的地点关联和第三种的局部纸物构图融入其中，保留清楚的内容顺序。

## 3. 用户、场景与成功标准

### 3.1 用户角色

- **回看者：**站点主人与伴侣，用手机或电脑浏览、读短记、看清照片。
- **内容维护者：**当前在项目中整理图片和清单；未来通过授权的维护入口上传与编辑。

本版前台对两人提供相同只读体验，不新增账户中心或管理面板。

### 3.2 核心场景

- 想看某个普通周末：从“日常”找到一组做饭、逛超市和窝在沙发上的照片。
- 想重看某次约会：凭封面或日期找到当晚的几张照片，读到一句只有两人懂的注记。
- 想找某次旅行：通过时间或地点找到该册，不将同城不同年份的旅行混在一起。
- 只想保存一张照片：一张也能成为一组完整回忆，不强制凑成相册。
- 找零散生活照片：允许维护者按“八月的小日子”等明确主题成组，保留各照片自己的日期。
- 想看清细节：打开完整大图，切换照片，再回到刚才的位置。

上述示例均为设计场景，不是用户已提供的真实经历。

### 3.3 成功标准

- 不解释操作方式，使用者可从首页打开一段回忆，再打开并关闭大图。
- 日常照片无需城市、坐标或旅行标题也能完整展示。
- 一次明确的筛选或地点选择后，能够找到已知回忆；失败时可清除筛选。
- 回看时能辨认照片、读日期和短句；纸物装饰不占据主要观看空间。
- 维护者新增一组内容只需资源和清单，不复制页面代码。
- 本版不采集使用数据作为前置要求；以任务式验收判断是否完成上述目标。

## 4. 产品结构与内容规则

### 4.1 基本单位：一段回忆

对用户可称“一段回忆”或“这一册”，对数据沿用已有 `Album`。不再额外新建一个含义相同的 Memory 实体。

一段回忆包含：**标题 + 封面 + 1 至多张照片 + 日期信息 + 可选地点 + 可选短记/标签**。

- 一次约会、一次旅行、一天的日常，可直接成组。
- 多天散片可按明确的月份或主题成组；不能自动把同城照片合并成一册。
- 一张照片默认归属一册；未来如需跨册引用，复用媒体 ID，注记和排版仍属于各自相册。
- 首批内容必须包含日常，不用纯旅行样本代替整体验证。

### 4.2 三个维度

- **时间：**全量内容的主组织方式，年月分段。允许只有年/月或完全未知。
- **生活标签：**可多选“日常、约会、旅行、纪念”，标签不是互斥目录；无标签内容仍进入“全部”。同一册可同时属于日常和约会。
- **地点：**可选显示名，如“家里”“楼下的小店”“杭州 · 西湖”。相册可以关联多个地点，无地点不影响保存、排序或观看。

### 4.3 导航层级

展柜 → 流光相册盒 → 回忆内页 → 照片大图。

“按地点找”是相册索引的另一种组织方式，最终进入同一个回忆内页。标签与年份用于筛选，不能把页面拆成互不相通的多个相册产品。

## 5. 版本范围与优先级

### P0：首版静态生活邮册

- R01：回忆票索引，包含封面、标题、日期、可选地点、短句和照片数量。
- R02：年月归档、生活标签筛选、分批展示。
- R03：地点文字索引与地点下的回忆列表。
- R04：回忆内页、照片级注记、完整大图和前后切换。
- R05：可选的一张人工精选“这一页，想再看一次”，不影响所有内容的可达性。
- R06：空、错、加载、长内容、缺少日期地点等状态。
- R07：静态图片与清单维护、资源分级、日夜主题和无障碍适配。

R05 无配置时整块省略，不生成随机内容或占位精选。

### P1：浏览增强

- 可交互的回忆地图，与现有相册和地点索引共享数据。
- 随机“翻到某一天”、文字搜索、更多自定义标签。
- 单册/单图深链与对应浏览器历史行为，集中设计路由后再加入。
- 可选导出一张回忆票，届时明确导出范围、署名和格式。

### P2：获得后端授权后

- 上传、编辑、排序与封面维护。
- 身份授权、存储、派生图处理、草稿/发布、备份迁移和失败恢复。

### 本版不包含

网页上传或拖放入口、假保存到浏览器、地图定位申请、实时轨迹、自动播放、旅行成就统计、天气、留言点赞、公开分享社区、整本 3D 翻书和模板制作器。

当前未开放的能力不显示灰色按钮或“即将推出”入口。

## 6. 核心页面需求

### 6.1 相册首页：一本正在积累的邮册

**页面首屏由上到下：**

1. 共享“返回展柜”。
2. 小题签“第二层 · 相纸”，主标题“流光相册盒”。
3. 建议副句：“把普通日子，也好好收藏。”
4. 可选的一张精选回忆票；没有精选则直接显示最近的回忆。
5. 年份选择、生活标签与“按地点找”轻量入口。
6. 年月分段的回忆票列表。

首屏必须看到真实照片入口，不用全屏引言、空信封或强制开盒动画占据第一屏。

**回忆票的信息顺序：**封面照片 → 回忆标题 → 日期/地点 → 可选一句话 → 照片数量。

- 标题描述经历，如“第一次一起煮面”“下班后多走了一站”，地点降为辅助信息。
- 标题、日期和地点放在纸面，照片不作为关键文字的复杂背景。
- 主封面建议 4:3；只裁切列表封面，允许维护者配置焦点。宽幅精选可采用横票形式，但不可因此裁掉人物。
- 纸票尾部可采用小缺口或虚线；邮戳只承担日期印记，不额外编造票号、面值或旅行认证。
- 同一入口只占一个键盘焦点，不把封面、标题和打开动作做成多个重复入口。

**排列与密度：**

- 桌面主要收藏区域通常三列，平板两列，手机一列。
- 桌面精选可为“照片在左、题签在右”的一张横票；手机将题签排到下方，仍使用相同信息顺序。
- 只在精选或页首露出少量背纸，正式列表不重叠、不随机旋转、不做信息被遮住的扇形堆。
- 首次展示 12 册，之后通过“再翻一些回忆”追加；追加不改变已浏览内容位置。数量是初始实现建议，可按真实素材验证调整。

### 6.2 分类与日期查找

- 默认“全部”，标签单选用于当前筛选，一册可命中多个不同标签。
- 年份与当前标签使用交集；可见地标明选择，提供“清除筛选”。
- 只有一个有效年份时不显示多余年份控件；仅显示存在内容的标签。
- 年月分段不是打卡热力图，不展示完成率、连续记录天数或空白月份缺口。
- 默认最新回忆在前，内容维护时产生与此一致的 `sortOrder`；前台遵守已保存顺序，不能由上传时间覆盖经历日期。
- 相同日期使用维护者设定顺序，稳定 ID 用于消除排序歧义；无日期内容归入“日期未记”。

### 6.3 地点索引：在熟悉的地方再相遇

- 点击“按地点找”后，将索引主内容切换为地点目录；返回按钮和相册标题保持稳定。
- 标题建议“那些熟悉的地方”，副句建议“远方和家门口，都有我们的回忆”。
- 每个地点条目由显示名称、一张来自其回忆的代表照片、回忆册数构成。
- 支持城市、生活地点别名和无地点分组；不要求行政区、城市编码或坐标。
- 进入“家里”可以看到不同日期的多册回忆，不把它们强行拼成一册。
- 多地点相册可出现在多个地点分组内，但全量相册只统计一次；照片与相册实体不重复保存。
- “未记地点”可以被浏览，不暗示内容损坏，也不强迫维护者补齐。
- P0 不绘制假地图、不将地点随机落点，不为“家里”推断真实住址。
- 进入地点索引时默认采用全量数据；该索引有独立的筛选状态，切换回按时间浏览时恢复原年份/标签，避免隐形筛选。

### 6.4 回忆内页：这一段日子的展开

**顺序：**返回全部回忆/返回地点 → 标题 → 日期与可选地点 → 可选短记 → 照片序列。

- 返回文案与真实来路一致，恢复原入口、筛选、已追加批次、滚动位置和焦点。
- 内页标题和短记是阅读开头；不要求再点击一个封面或播放按钮才能看照片。
- 桌面两列逐行排版，宽幅照片可独占一行；手机一列。遵守照片顺序，不用瀑布流自动调换照片以填空。
- 组内照片原比例展示，纸边宽度统一；无注记时不留一个空文案框。
- 相册封面本身按组内顺序出现，不在页首额外复制一次巨幅封面。
- 超过 24 张时通过“继续看这一册”追加。大图浏览按全册顺序，关闭时自动展开当前照片所在批次并恢复焦点。
- 不为一张照片的相册制造占位卡或强迫分页。

### 6.5 大图查看：让照片占据主位

- 点击照片后在独立顶层打开查看器，完整显示原比例，纸票缺口、邮戳和胶带从观看区域退场。
- 可见操作为关闭、上一张、下一张、张数和简短说明；一张照片时不显示切换。
- 第一张/最后一张明确禁用对应方向，不循环回到开头。
- 日期和地点优先显示照片自身信息。只有相册信息时使用“这一册：……”说明，不伪装成照片的准确拍摄日期。
- 桌面可带缩略序列；手机优先保留大图、说明和切换控件，缩略序列只在空间足够时展示。
- 支持方向键、Escape 和可点击按钮；触摸轻扫是补充，不能成为唯一操作方式。
- 页面原生缩放保持可用；自定义捏合平移不作为 P0 必需功能。
- 打开时锁定背后的滚动，将焦点放入查看器；关闭恢复原照片焦点和浏览位置。
- 横屏短屏与 200% 缩放下，说明允许内部滚动，关闭控件始终可达；仅在空间不足时采用这个滚动区域。

## 7. 视觉规范：温暖来自纸与生活本身

### 7.1 材料与颜色

- 沿用暖白纸面、深木色文字和全站日夜主题。优先使用现有 `--story-*` 语义变量，基础参考为 `#FDFBF7`、`#2D241E`、木色与纸边线。
- 朱印/玫瑰印色只用于一处日期印记或选中标记，沿用现有印色令牌；不能以粉色覆盖全部背景。
- 图片原色保留，夜间只改变周围环境、纸边和控件；不对人像统一加泛黄、褐色或暗化滤镜。
- 纸张颗粒限定在边缘和空白区域；文字和图像保持清楚。
- 缺口、虚线、轻阴影表达一张票的轮廓；每张票不同时堆满齿孔、胶带、爱心、蜡封、邮戳和折痕。

### 7.2 字体和留白

- 回忆标题使用现有阅读字体，日期/地点使用清晰的界面字体，手写只用于短注记。
- 中文标题承担主要层级；不用全大写城市拼音和超宽字距制造风格。
- 正文建议约 16px，日期地点建议不小于 14px；遵守字体回退和 200% 缩放。
- 手机边距建议 16–20px，桌面内容宽度建议约 1080px，以照片实际观看面积校正。
- 模块之间允许留白，同一模块内部紧凑；不把一张照片压成小缩略图以腾出装饰舞台。

### 7.3 动效与主题

- 拿起一张票：轻微抬起或短距位移；进入内页：约 280ms 淡入；控件反馈：约 160ms。
- 沿用全站动效令牌，减少动态效果时直接切换或短淡入。
- 不自动翻动、播放音乐、轮播精选或让纸片持续漂浮。
- 四季只影响少量边角点缀，不能遮住照片、改变位置或修改回忆日期。

## 8. 日期、地点与数据边界

本节描述产品语义，不规定代码实现。实施需遵循并最小扩展现有领域与仓储契约。

### 8.1 复用已有内容

- 复用 `Album` 的稳定 ID、标题、说明、经历日期、精度、地点、封面和有序媒体引用。
- 复用 `AlbumPhoto` 的注记、拍摄日期、地点和宽幅标记。
- 复用 `MediaAsset` 的资源地址、替代文本、尺寸、媒体类型和加载角色。
- 现有 `photos` 与 `mediaAssetIds` 并存时必须保证引用与顺序一致，约定唯一规范化读取结果，不能由两个组件各用一份冲突的顺序。

### 8.2 P0 需要补足的语义

- 可选生活标签列表；不将标签写入图片文件名。
- 可选精选相册 ID，只选择现有可展示相册，不复制照片和文案。
- 多地点关联：稳定地点 ID、显示名、可选城市名；兼容已有单一 `location` 文本，不按同名自动合并不同地方。
- 图片缩略/常规/大图派生版本，以及可选封面焦点；多个版本关联同一媒体 ID。

是否将地点定义放入只读内容仓储的新接口，还是作为相册元数据注册，应在实现准备阶段确定；页面不能直接依赖地图供应商 DTO。地图坐标不是 P0 必填字段。

### 8.3 不变式

1. **发生日期不等于录入日期。** 补录旧照片不应排在最新经历之前；未来上传顺序也不替代照片叙事顺序。
2. 日期可精确到日、月、年或未知；只记得月份就显示月份，不补成某月 1 日。
3. 跨日相册显示区间；跨年按开始年份归档。合集的单图保留各自拍摄日期。
4. 日期值按所记录的日历语义显示；有具体时刻时才连同来源时区处理，避免自动换算使日期偏移。
5. 地点显示名可为“家里”“附近”，也可以缺省。前台不重复用“地点未记”打断每张日常照片；在地点索引中才设独立未记地点分组。
6. 相册是默认地点，照片可覆盖。没有照片级覆盖时可显示相册语境；不能由整册地点推断照片精确坐标。
7. 标题可重复，ID 不可重复；封面必须属于该相册。
8. 缺媒体、空册、无效日期区间等在静态清单校验阶段发现；运行时仍提供可返回的容错状态。
9. 静态文件发布不提供身份授权能力。项目的私密氛围不能被文案描述成“已加密”“只有你们能访问”。

## 9. 后续地图需求（P1，暂缓实现）

地图是一种可选浏览方式，不决定照片是否有资格进入相册。

- 用户主动进入“回忆地图”后加载地图模块，默认相册首屏不请求地图 SDK、地图瓦片或地理数据。
- 地图仅展示维护者确认可定位的地点；“家里”、无坐标和刻意模糊的地点保留在同级文字目录中，不提供精确点位。
- 点击点位 → 显示地点名称和关联相册 → 打开同一回忆内页。关闭后回到原地图范围与选中点。
- 多个地点过近时聚合或列出候选，手机不要求点中很小的标记；同时提供地点列表替代交互。
- 默认不连线。跨多地的一次旅行只有在提供明确顺序后才可查看路线；连线为回忆示意，不代表导航路线。
- 地图不可用、断网、无坐标时，地点列表和相册仍可工作，不能整页空白。
- 真实底图与坐标系匹配，坐标来源明确；范围适配已有内容，不预设只允许国内照片。
- 若启用外部地图服务，应保留其署名，明确网络依赖；底图来源、许可、供应商和数据方案在 P1 前确定。本版不选择具体服务，也不凭参考项目存在就复制其地图数据。
- 不采集当前位置，不自动推断住址，不加入国家/城市占领率与旅行排名。

## 10. 状态、无障碍与性能

### 10.1 状态文案与行为

- **无内容：**“相册盒里，还没有放入照片。”辅句建议“普通的一天，也值得留一张。”提供返回展柜；不出现上传入口。
- **筛选无结果：**“这一页还没有相应的回忆。”提供清除筛选。
- **无地点数据：**地点入口仍能解释“有些日子，只记下了照片”；展示未记地点回忆，不画空地图。
- **单图加载中：**按真实尺寸占位，已经加载的标题、日期和返回可操作。
- **单图失败：**保留位置与重试；在查看器中可以继续切图或关闭。
- **模块失败：**复用共享错误边界的重试与返回，不另做一套错误页。
- **空册或失效 ID：**显示可理解的说明和返回；正式发布前应由清单校验拦截。
- **缺日期：**归入“日期未记”；不显示 1970 年或录入日。
- **长文本：**标题换行，内页显示完整文字；重要信息不能只能通过 hover 获得。

### 10.2 无障碍与响应式

- 主要触控目标约 44px；所有按钮有可访问名称、可见焦点和明确状态。
- 日期、地点、相册名具有文本表达，不能只藏在邮戳图形、地图点颜色或手写图片中。
- 大图为对话框，进入/关闭焦点合理，背景不可交互；不将整段内容设为不可选择。
- 正文对比度和控件对比度按项目无障碍要求校验；木色辅助字不能因纸纹而失去可读性。
- 相册首页和内页沿用 ViewportShell 的单一纵向主滚动区、`dvh` 和 safe area；不套用七夕 v2 的单屏限制。
- 360px 手机、平板、桌面、横屏短屏以及 200% 缩放都应可看图、读字和返回。

### 10.3 资源策略

- 首页只加载可见的封面派生图；进入一册再加载相册展示图；点击大图再请求大图版本。
- 不因展柜入口 hover 预取整套照片；不因为地点索引存在而加载地图。
- 图片声明宽高或比例，延后加载非首屏内容；同一图片请求去重。
- 手机首页新增图片传输量建议目标约 500KB 内，实际尺寸、清晰度与预算由真实素材测试确定，不宣称该数值已达到。
- 首屏不等待全部图片；大图打开后如需相邻预取，限制为相邻一张，离开相册后取消无关任务。
- 原图保留在发布路径外，生成压缩派生图，不在内容清单中内嵌 Base64。
- 60 册、单册 100 张作为建议压力样本；它们是验收条件，不是首批照片数量要求，也不是永久内容上限。

## 11. 内容维护与未来上传

### 11.1 当前静态维护流程

选照片 → 决定回忆组与标题 → 填写已知日期/地点 → 选择封面与照片顺序 → 生成派生图片 → 维护内容清单 → 本地预览 → 项目验证 → 按授权发布。

- 图片与本地清单保留在相纸专题边界；通过 adapter 提供领域内容。
- 每册至少一张图；一段日常不要求“旅行城市”“目的地”或 GPS。
- 用户真实照片不足时，用明确标记的测试数据验证布局，不能把参考截图里的照片当成两人的内容。
- 按 [媒体来源规范](../../Cabinet/docs/MEDIA-PROVENANCE.md) 记录来源、派生版本和发布选择；上传用原图和公开展示版本区分管理。

### 11.2 未来上传流程

新建/选择一册 → 选择照片 → 确认日期 → 可选地点与标签 → 一句话 → 排序/选封面 → 预览 → 保存并发布。

- 批量上传失败应保留成功项、指出失败项并支持重试；照片顺序不随上传完成先后改变。
- EXIF 仅作为可确认的日期/位置建议，不可静默把 GPS 发布为地点；没有 EXIF 不阻止保存。
- 不需要为了上传再维护一套相册数据。现有稳定 ID、封面、顺序、日期和注记均可迁移。
- 写入权限、对象存储、资源处理、草稿发布与数据备份是独立后端任务，不在浏览组件中直接加入存储 SDK 或密钥。
- 当前仓储是同步只读边界；未来远程读取需要明确异步加载/快照、错误和 URL 过期处理，不能承诺只替换一个资源地址即可完成后端迁移。

## 12. 执行计划与职责

本节是后续执行计划，本轮不执行页面实现。

### 第一步：确认 PRD 与内容样本

设计负责人确认回忆票、日常覆盖、地点可选、地图优先级及版本范围；内容维护者提供真实照片与文案。

完成条件：至少能描述一组日常、一组约会、一组旅行、单图组和无地点组的表现。真实素材可跨场景复用，但不能捏造用户经历。

### 第二步：制作视觉样稿

交付桌面和手机首页、地点目录、回忆内页、大图、夜间及空状态关键稿。

完成条件：首屏出现真实内容入口；日常与旅行同样自然；照片清晰、日期可读，纸物装饰克制。样稿评审聚焦布局与视觉，不需要先接入后端。

### 第三步：确定内容契约与静态清单

复用已有日期/地点/封面字段，补充标签、地点关系、媒体派生图与精选配置；明确两套照片引用字段的一致性约束。

完成条件：一份规范化内容可以同时驱动时间索引、地点索引、内页和大图；新增一册不改页面布局代码。

### 第四步：按模块实现 P0

主要责任范围为 `Cabinet/src/pages/gallery/`，必要时最小调整领域模型与本地 adapter。保留 `#photos` 入口和现有页面 Props，优先复用可用浏览逻辑。

- 索引、回忆票、地点目录、内页和大图按职责组织，但不提前提升成全站通用框架。
- 保持路由懒加载；如需 loader，遵循 pageRegistry、PageSlot、routes、siteConfig 和 lazyLoadViews 的既有链路。
- 导航仍通过 App 的 `navigateTo()`；页面内浏览状态不自行创建第二套路由。
- P0 不承诺单册刷新恢复或浏览器后退逐层关闭，显式返回控件必须可靠。P1 深链时统一补充这些行为，不做零散 History 拦截。
- 使用稳定 ID、纯类型导入、兼容的 React 依赖和浏览器定时器清理；不新增地图/翻书/复杂编辑器依赖。
- 只改必要源码，不手工修改根目录 `assets/`、`pages/` 或 `index.html`。

### 第五步：验收与文档收口

按下一节逐项验收，执行项目 `npm run verify`；新能力完成后再更新当前架构和内容契约的事实说明。

设计负责人负责视觉、内容层级和完整体验评审；开发执行者提供截图、交互和网络加载证据；维护者按 SCOPE 决定何时发布。

### 第六步：后续增强

P0 使用真实照片稳定后，再按授权开启 P1 地图或 P2 上传。地图优先级可以调整，但不会改变“日常与旅行共用一套回忆内容”的核心契约。

## 13. 验收清单

- AC01：无标签、无地点、无坐标的一张日常照片可以成册，并出现在“全部”。
- AC02：同一城市的两次约会可分别找到；一册关联多地点时不重复计算总册数。
- AC03：日/月/年/未知日期与跨日区间正确显示；补录旧内容不误用录入时间。
- AC04：标签和年份筛选结果正确，可清除；切换时间/地点索引不留下不可见的筛选。
- AC05：封面可裁切但不截掉关键人物；内页和大图完整显示横、竖、全景图。
- AC06：从时间或地点进入同一册时内容一致；返回恢复原来入口、焦点和滚动位置。
- AC07：大图方向键、关闭、触控按钮可用；首尾边界明确，关闭后定位正确。
- AC08：超过分批数量后仍能完整浏览，追加不跳到页首；从大图返回未展开批次能找到当前照片。
- AC09：空册、无内容、坏图和模块失败均有恢复路径，单图失败不阻止整册观看。
- AC10：360px、390px、768px、1440px、横屏短屏、200% 缩放、日夜与减少动态效果均通过检查。
- AC11：首页没有强制开场、自动播放、不可用上传按钮和旅游成就统计；日常样本在视觉上不显得像填错了旅行模板。
- AC12：网络记录证明展柜不下载相册照片，索引不下载全册高清图，P0 不请求地图服务。
- AC13：静态清单检查重复 ID、缺失媒体、封面归属、日期有效性、空册和引用顺序；派生图与原图的发布范围正确。
- AC14：执行 `cd Cabinet` 后 `npm run verify`，包括类型、生产构建、性能预算、草稿泄漏、文档链接和关键路由 smoke test；通过不等于已发布。
