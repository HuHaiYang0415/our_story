# 相纸 · 流光相册盒：页面设计与执行方案

> 本文保留 2026-09-15 的初版调研与设计记录。后续相册需求以 [2026-09-17 生活邮册 PRD](PRD-2026-09-17.md) 为当前提案入口；初版中的源码现状、范围与设计选择不再代表最新状态。实施与发布许可仍以根目录 SCOPE.md 为准。

## 1. 结论与已确认需求

推荐方向：**把每次约会、旅行装订成一册，按年份收进相册盒。**

用户已确认按一次约会或旅行成组，每组具有标题、日期、地点，组内保存多张照片。本版由维护者整理本地图片资源和内容清单，通过现有构建发布流程展示。未来再增加上传和内容维护入口。

本提案负责页面结构、视觉、交互、内容契约建议、执行边界和验收。尚未制作视觉样稿、编写页面代码或接入上传。以下布局与交互是建议方案，不是已批准的视觉基线。

### 当前事实与权威边界

- 当前范围、正式基线、实施和发布许可，始终以 [SCOPE.md](../../SCOPE.md) 为准；本提案不重定义 Git 基线，也不沿用其他专题的发布授权。
- 产品和视觉遵循 [PRODUCT.md](../../PRODUCT.md)、[DESIGN.md](../../DESIGN.md)。这是情侣纪念站中的回忆浏览页面，体验以照片为主。
- 当前入口为 `#photos`，页面标题为“流光相册盒”。[PolaroidGallery.tsx](../../Cabinet/src/pages/gallery/PolaroidGallery.tsx) 仍是“装修中”占位页，没有实际相册展示。
- 当前 [本地只读仓储](../../Cabinet/src/data/localContentRepository.ts) 的相册集合为空。[Album](../../Cabinet/src/domain/content.ts) 只有标题、描述和媒体 ID 等基础字段，尚无相册日期、地点、封面等字段。
- 当前工作树中，页面定义集中于 [pageRegistry.ts](../../Cabinet/src/app/pageRegistry.ts)，相册由 [PageSlot.tsx](../../Cabinet/src/app/PageSlot.tsx) 懒加载；[routes.ts](../../Cabinet/src/app/routes.ts) 从注册表派生 Hash 映射。执行时应同时阅读当前源码与仓库规则，避免按历史结构再建一套注册方式。
- 相册改造不涉及展柜、信箱、关系页、节日专题的重设计，也不修改全站视觉约定。

## 2. 网站参考及取舍

调研日期：2026-09-15。已搜索并读取以下官方页面；浏览器视觉预览超时，因此本轮不声称完成了这些网站的逐屏视觉或交互审计。下列“用于本项目”部分为设计推导。

### Exposure：以一组照片讲述一段经历

[Exposure 官方网站](https://exposure.co/) 将照片、文字和其他媒体组织成故事，并支持按故事呈现的站点入口。

用于本项目：一次约会或旅行对应一个完整的观看单元；进入后由照片和少量文字建立节奏。首页不把不同经历的照片全部打散。借鉴内容组织方式，不引入其社交、订阅或商业发布功能。

### Polarsteps：经历与地点一起保存

[Polarsteps 官方网站](https://www.polarsteps.com/) 以旅程组织照片、故事和路径，也提供将旅程保存为 Travel Book 的方式。

用于本项目：每册先交代“什么时候、在哪里”，跨日旅行可以显示日期区间，照片可补充具体拍摄地点。当前只记录地点文字；路线地图、自动定位、轨迹和旅行统计不进入本版。

### Artifact Uprising：日常值得成为一本小相册

[Everyday Photo Book 官方介绍](https://www.artifactuprising.com/inside-look/everyday-photo-book) 使用织物封面、平展内页和日常照片，强调为不同生活片段制作独立相册。

用于本项目：以纸张留白、相片边缘和简短题签建立保存感；借鉴“小册”的尺度与内容关系。照片保持自己的颜色，不仿制印刷滤镜，也不复制电商页面。

### 三种可行结构

1. **相册索引 + 回忆内页，推荐。** 一次经历一册，入口容易辨认，内容增加后仍可查找，最符合已确认的分组习惯。
2. **按经历分区的散落相纸墙。** 开场亲近、手作感强，但照片增多后会拉长页面，日期地点不易扫描；适合少量精选照片，不作为完整相册主结构。
3. **仿实体书逐页翻阅。** 仪式感强，但横竖照片、小屏、短屏和长说明难以同时适配，逐页操作也增加寻找成本；不列入本版。

采用第一种结构，把相纸的厚度、题签、轻微叠放作为局部材料语言。

## 3. 页面结构：三层浏览

浏览路径：**展柜 → 相册索引 → 某次约会/旅行 → 单张大图**。

### A. 相册索引：找回某一次经历

从上到下依次为：

1. 共享返回控件“返回展柜”。
2. 小题签“第二层 · 相纸”，主标题沿用“流光相册盒”。可选副句：“把一起走过的日子，一册一册收好。”副句是建议文案。
3. 年份分段与相册封面。
4. 内容较多时的“再看一些回忆”按钮。

首屏直接出现真实相册封面，不先展示全屏引言或开盒动画。没有真实照片时使用空状态，不能用素材库照片冒充两人的经历。

**一册的可见内容：**

- 一张由维护者指定的代表照片。
- 相册标题，优先描述具体经历。
- 日期或日期区间。
- 地点，例如城市与地点名。
- 照片数量，作为轻量说明。

仅用于排版的虚构示例：

> 沿着湖边慢慢走  
> 2026.05.16 · 杭州 · 西湖  
> 12 张相纸

示例不得未经替换进入正式内容。

**封面与排列：**

- 桌面通常三列，平板两列，手机一列；封面宽度不足以清晰显示标题和日期时提前减列。
- 封面照片使用统一横向窗口，建议 4:3，明确这是封面裁切；允许维护者指定裁切焦点，保证人物完整。
- 封面外为暖白纸边，下方是题签。可有一层轻微露出的背纸，背纸不另加载照片。
- 一个相册整体为一个可访问入口，避免图片、标题和按钮重复占据多个 Tab 焦点。
- 相册按年份分段。默认最新经历在前，维护数据时写入确定的排序；页面遵循仓储 `sortOrder`，不临时建立第二套排序规则。
- 有多个年份时才显示年份选择；只筛选年份，不同时增加地点、标签、搜索和地图工具条。
- 建议初次渲染 12 册，超过后显式追加。追加后保留当前位置并播报新增数量；筛选切换重置批次。

### B. 回忆内页：完整看完这一次

选择相册后，在相纸页内部切换到该册的浏览状态，不同时弹出一层相册弹窗。

阅读顺序为：**返回全部相册 → 标题 → 日期与地点 → 可选的一段短记 → 照片序列 → 回到全部相册**。

- 内页不重复放一张独立巨幅封面。封面照片仍按维护者指定顺序出现在序列中，避免同一张图连续出现两次。
- 标题和说明放在干净纸面，不压在人物或复杂照片上。
- 桌面和平板默认两列、逐行排列；手机一列。照片保留原始比例，不以瀑布流重排叙事顺序。
- 同一行高低不一时允许留白；少量宽幅照片可由内容清单标记独占一行。不能因排版自动打乱顺序。
- 每张图下方可带一句注记。关键日期、地点不是必须翻到背面或悬停才可见。
- 相册通常为 6–30 张；一张照片也能成册，不制造空格填充。
- 超过 24 张时采用“继续看这一册”追加照片。大图浏览仍以整册的稳定顺序为准，从大图返回未渲染照片时先展开其所在批次，再恢复位置。
- 上述数量为本版建议分批值，不是内容总量上限；最终根据真实照片和设备验证调整。

### C. 单张大图：看清照片

点击任意照片进入覆盖全视口的大图查看器。

- 原比例完整展示，保留横图、竖图和全景图的边界。
- 控件包括“关闭大图”、上一张、下一张和“3 / 12”；无多张照片时隐藏前后切换。
- 日期、地点、短注记位于独立说明区。优先显示该照片自己的信息，再使用有明确语义的相册信息。
- 桌面可将说明放侧边；手机放下方。短屏或 200% 缩放下，说明区允许滚动，关闭和切换控件始终可达。
- 本版支持完整大图观看与浏览器原生页面缩放；自定义双击缩放、捏合和平移不列为必需能力。
- 第一张和最后一张不循环跳转，使用禁用状态明确边界。

## 4. 视觉与布局约束

### 延续全站材料

- 背景、正文、辅助文字、边线使用现有 `--story-surface`、`--story-ink`、`--story-ink-muted`、`--story-line`。
- 日间以现有暖白纸张和木色为基础；少量木色用于题签、索引和活动状态，不另建相册配色系统。
- 夜间跟随现有主题变量改变环境、纸边和控件，照片像素保持原样，不统一压暗或加暖色滤镜。
- 纸张质感集中在空白边缘，避免颗粒叠在照片和正文上。无需额外整屏纹理图。
- 封面可使用极轻的不规则背纸；文字与主要交互区域保持水平。不要让每张照片都随机旋转。
- 季节变化最多影响一处小题签或边角点缀，不能改变照片布局、阅读对比度或内容日期。
- 现有占位页的工具图标、持续粒子、装修文案、预计完成时间在实施时整体移除。

### 字体、密度与观看尺度

- 主标题和相册标题使用现有衬线角色；辅助日期、地点、计数使用界面字体；手写字只用于短注记。
- 建议标题在手机约 24–28px、桌面约 30–36px；内容正文约 16px，日期地点不低于约 14px。最终以现有字体实际字面和缩放验收为准。
- 页面内容宽度建议控制在约 1040–1120px；手机保留约 16–20px 侧边距，给照片足够观看面积。
- 纸边、照片和文字靠间距建立层次，不为每段说明加圆角容器、胶带和印章。

### 滚动边界

- 相册索引和回忆内页沿用 [ViewportShell](../../Cabinet/src/shared/layout/ViewportShell.tsx)，由主内容区承担唯一纵向滚动。
- 固定应用壳、动态视口和 safe area 行为继续沿用；禁止相册页面横向溢出和多个内容滚动条相互争抢。
- 返回区域保持可达；短屏先压缩装饰与留白，再让内容正常滚动。
- 七夕 v2 的“一页单屏”是其专题约定，不应用到需要持续积累内容的相册。
- 大图打开时锁定背后的相册滚动，关闭后恢复，不重置到页首。

## 5. 交互与状态

### 返回、焦点与地址

- 索引的“返回展柜”继续调用现有回调，由 `App.tsx` 的 `navigateTo()` 导航。
- 内页的“返回全部相册”恢复此前年份、已展开批次、滚动位置和封面焦点。
- 大图的“关闭大图”返回原照片，恢复焦点和内页滚动位置。
- 本版保留 `#photos` 这一站点路由；相册 ID、当前照片 ID、筛选和浏览位置是页面内状态，刷新回到相册索引。
- 不自行新增 `#photos/某册` 或劫持全站浏览器历史。浏览器后退沿用既有站点行为；页面内三级返回通过明确控件完成。子相册深链、刷新恢复和浏览器后退逐层关闭若成为要求，另列集中路由改造任务。

### 输入方式

- 所有照片入口和操作控件具有明确名称、可见焦点、约 44px 的最小触控热区。
- Enter/Space 打开相册或照片；大图内左右方向键切图，Escape 关闭。
- 大图使用正确的对话框语义和焦点约束；背景不接受键盘交互，关闭后焦点回到触发位置。
- 手机可以增加水平轻扫切图，但同等可达的按钮必须存在；轻扫不妨碍说明滚动和原生缩放。
- 不以 hover 作为显示日期、地点、返回或照片标题的唯一方式。

### 动效

- 沿用共享 160/280/480ms 节奏，以淡入、短距离移位和轻微抬起表达拿起相纸。
- 建议主要状态切换约 280ms，控件反馈约 160ms；不加入强制开场、自动轮播、翻书锁定或 BGM。
- `prefers-reduced-motion` 下直接切换或简短淡入，保持全部内容和反馈可见。
- 退出相纸页或关闭大图时，清理页面事件、预取队列和计时器；不留下后台动画。

### 异常与边界

- **完全空相册：**“相册盒里，还没有放入照片。”搭配轻量纸面和返回入口。访客界面不出现“上传”“服务器未连接”或虚假的进度。
- **年份无结果：**“这一年还没有相册”，提供“查看全部”。
- **空册：**正式内容清单校验时阻止发布；若运行时遇到，保留标题说明和返回，正文显示“这一册暂时没有照片”。
- **单图加载失败：**保留原比例占位，提供“重新加载”；其余图继续可看。
- **页面模块失败：**复用现有页面错误边界、重试和返回。不能用“一张图片失败”触发整册永久不可用。
- **无日期/地点：**不生成虚假精确值；旧内容归入“日期未记”，缺少地点显示“地点未记”。新内容优先在资源清单阶段补齐。
- **长标题和长地点：**封面题签正常换行，大图与内页显示完整文本；不能只靠省略号和 hover 查看。
- **重复标题：**允许，以稳定 ID 区分；缺失媒体引用、重复媒体 ID、非法尺寸和无效日期在构建前报告。

## 6. 日期、地点与内容契约建议

遵循 [内容领域与仓储契约](../../docs/CONTENT-CONTRACT.md)。以下是最小扩展建议，实施前由维护者确认字段语义并更新契约；本轮不修改类型文件。

### 相册层

在现有 Album 基础上补足以下概念：

- 稳定 ID、标题、可选的一段说明。
- 经历开始日期、可选结束日期及日期精度。
- 地点显示名称；如有多个目的地，允许维护一个明确的概括名称。
- 封面媒体 ID、照片有序 ID 列表。
- 必要时的封面裁切焦点和照片独占整行标记。
- 沿用 `spaceId`、`sortOrder`、可见性、创建/更新时间语义。

开始/结束日期描述经历本身。`createdAt` 是内容被加入系统的时间，未来上传时间不得代替拍摄或旅行日期。

### 照片层

- 复用 MediaAsset 的稳定 ID、类型、URL、宽高、替代文本和加载角色。
- 增补缩略版本、常规展示版本、大图版本的表达能力；它们属于同一个媒体，不建立互不关联的三张照片记录。
- 可选实际拍摄日期、地点和简短说明。裁切、宽幅排版等属于本册中的展示偏好，避免写成所有复用该照片的页面都必须继承的全局属性。
- 图片文件名、数组位置和资源 URL 均不能代替稳定 ID。

字段实际命名、可选性及相册与媒体之间的关联表现形式，在执行步骤 1 中确定，避免页面自建一份与领域模型冲突的照片类型。

### 显示与排序规则

1. 相册支持单日与跨日区间，示例格式为 `2026.05.16`、`2026.05.16—05.18`；跨年显示完整年份。
2. 只确定月份或年份时按原精度展示，不补成某月 1 日；未知日期独立分组。跨年相册按开始年份归档。
3. 日期型内容保持当地日历日期语义，不经 UTC 转换后漂移一天；有具体时刻才同时保存其时区语义。
4. 地点由维护者明确填写，本版不读取浏览器定位，不调用地理编码或地图服务。
5. 照片有独立拍摄信息时优先显示；没有时标明“本次旅行：日期区间 · 地点”，不能将整次旅行的第一天冒充该照片拍摄日。
6. 新加入相册按经历日期生成初始排序，之后由已保存的 `sortOrder` 决定；同一天内容可手工确定先后。组内顺序由维护者明确设置，不依赖上传完成顺序或文件名。
7. `visibility` 只是当前内容状态，静态文件被发布后并不因此获得访问保护；产品不能标记为“已加密”或“仅你们可见”。正式资源应是维护者选择可按当前托管方式发布的版本。

## 7. 本版如何维护照片

本版的“加入相册”发生在项目内容维护流程，访客页面保持只读。

1. 按一次约会或旅行选定照片，确定标题、日期、地点、照片顺序与封面。
2. 保留原始文件在发布路径之外，生成适合网页的派生版本；原图不被源码导入。
3. 发布用图片放在 `Cabinet/src/pages/gallery/` 内的专属资源目录，建议按年份与稳定相册 ID 组织。
4. 相册本地清单放在相纸模块内，再由本地 adapter 转换为既有领域仓储结果。图片与本册展示状态不提升到共享层。
5. 维护者每增加一册，只补图片与内容清单，不复制页面组件或为每本相册添加一条全站路由。
6. 按 [媒体来源记录](../../Cabinet/docs/MEDIA-PROVENANCE.md) 登记来源、派生版本和必要的隐私处理；公开版本仅保留展示所需元数据，不附带无关的精确 GPS 信息。
7. 本地预览、内容校验、完整验证后，再按当前范围文档确定的许可发布。

访客界面本版不提供上传按钮、拖放区域、编辑、删除和“即将开放”占位按钮，也不用 localStorage 或 sessionStorage 冒充照片存储。

## 8. 加载与性能约束

沿用 [资源加载规范](../../Cabinet/docs/RESOURCE-LOADING-GUIDELINES.md)，以下相册专项目标待真实资源验证，不替代仓库现有性能门槛。

- 相册索引只请求当前需要的封面派生图；进入一册后才请求其展示图，打开大图后才请求高清派生图。
- 保持相纸页懒加载。相册清单和图片地址的注册不能把整套相册 JavaScript 及媒体预取带回展柜首屏；若仓储采用同步快照，应在进入相册时由其局部 loader 准备，不能在每个调用仓储的页面都提前装载。
- 首屏照片单独加载并显示固定比例占位，返回和索引不等待全册图片。非首屏使用原生懒加载。
- 不在展柜入口 hover 时预取整册；用户打开大图后至多预热相邻一张，并尊重节流条件，切换相册后取消无关队列。
- 建议封面/缩略图长边约 640–960px，常规展示约 1280px，大图约 1920–2560px。小图不强行放大；尺寸以真实展示宽度和画质复核为准。
- 建议移动端索引首屏新增图片总量控制在约 500KB 内，常用封面争取 60–120KB；这是提案目标，不是声称已测得的结果。复杂照片先比较画质再压缩。
- 原图保留、发布派生图；不把 Base64 照片内嵌进 TS/JSON，不把未选照片混入生产 glob。
- 明确宽高或比例以稳定占位。封面优先选择浏览器实际需要的分辨率，避免下载高清图后再压成小格。
- 单图失败允许重试，重试不得被失败缓存永久拦截；大图不加载成功也可以关闭。

## 9. 未来上传如何接入

未来维护流程建议为：**新建/选择相册 → 选择照片 → 填写或确认日期地点 → 排序与选封面 → 预览 → 保存发布**。

前台相册继续读取同一领域内容。未来增加的编辑入口仅向有维护权限的用户开放，访客继续使用本方案的浏览界面。

现在需要保留的只有稳定内容 ID、明确的日期地点语义、相册与媒体关联、媒体派生版本和只读仓储边界。

以下留给获得单独授权后的后端任务：

- 登录、维护权限、服务端授权和具体对象存储选择。
- 文件上传、格式校验、派生图生成、失败重试、重复上传处理，以及草稿到发布的完整状态。
- 将现有静态内容作为可重复导入的种子，保留相册和媒体 ID、日期、顺序、封面与说明。
- 为远程读取补足异步加载、错误、取消与 URL 过期处理。当前仓储是同步只读接口，不能承诺“直接替换一个 URL 就接入后端”；届时应明确采用加载后快照还是版本化异步接口。
- 写入能力使用独立的维护边界，不向现有只读仓储临时追加上传函数，也不在展示组件中直接调用存储 SDK。

## 10. 后续执行计划

以下步骤供后续被授权的执行会话使用，本轮全部处于待执行状态。设计负责人在各阶段评审交付物；开发执行者遵循既有代码和发布规范。

### 步骤 1：锁定页面方案与内容契约

输入：本提案、现有项目基线、首批照片的大致数量和横竖比例。

交付：确认相册索引、内页、大图三种状态；确定日期精度、地点继承、媒体派生版本和排序字段；确定暂不支持子相册深链的边界。

完成条件：明确每个字段由谁维护、缺失时怎样显示、未来上传如何保持原有语义；在得到实施许可后同步内容契约和任务范围。

### 步骤 2：制作静态视觉样稿

交付：桌面索引、手机索引、桌面/手机回忆内页、大图以及夜间和空状态关键样稿。

完成条件：首屏照片可辨认，日期地点可直接阅读，长标题和横竖照片共存，真实照片不被滤镜处理，手机不依赖横向拖动才能看完内容。

没有真实素材时只制作明确标注的排版样本；正式视觉验收需用实际照片再检查裁切与色彩。

### 步骤 3：整理首批静态内容

交付：图片派生版本、相册清单、稳定 ID、封面、顺序、日期地点与来源记录。

建议覆盖一册单日约会、一册跨日旅行，以及至少一张竖图和一张宽幅图；这是验收样本需求，不是要求用户必须拥有这些经历。

完成条件：清单无缺失媒体引用，原图不进构建，加入一册不需要改页面布局代码。

### 步骤 4：实现只读相册与浏览状态

主要责任范围：`Cabinet/src/pages/gallery/`；按步骤 1 的契约最小调整 `domain/content.ts` 与 `data/localContentRepository.ts`。

交付：索引、年份分段、回忆内页、大图、追加加载、滚动和焦点恢复，以及全部空/错状态。

代码要求：

- 页面通过仓储边界读取内容，不直接依赖未来 API DTO 或数据库模型。
- 模块按索引、内页、大图、资源与内容组织，先在相纸目录复用；不为单页提前建设全站通用相册框架。
- 保留 `PolaroidGallery` 入口兼容，使用 `import type` 和稳定 ID 作为 React key；不把 `key` 定义为业务 Props。
- 继续使用现有 React、motion 与图标依赖，初版不新增翻书、地图、瀑布流或全功能媒体管理库。
- 如需 loader，仅对 `PageSlot`、`pageRegistry` 和现有懒加载/标题链路作必要集成，不将相册主组件静态导入 `App.tsx`。
- 遵循 `window.setTimeout`/`window.setInterval` 和 effect cleanup 约定。
- 不手改根目录发布产物；不改其他页面以配合相册布局。

完成条件：核心链路可由鼠标、键盘与触控完成；本版无上传、编辑或假存储能力。

### 步骤 5：资源、跨设备与回归验收

交付：各状态的桌面/手机截图、资源请求记录、验证结果与未解决问题清单。

验收范围：

- 约 360px、390px、768px、1440px 宽度及横屏短屏；200% 文字缩放。
- 日夜主题与季节点缀；系统减少动态效果开启。
- 0 册、1 册、多年份、长标题、缺日期/地点、坏图，以及建议压力样本 60 册、单册 100 张。压力数据必须明确为测试数据，不随正式内容发布。
- 关闭大图后位置与焦点不丢失；内页返回索引后筛选和位置恢复。
- 直接打开 `#photos`、刷新、从展柜进入和返回；既有路由不回归。
- 网络记录证明：展柜没有额外下载相册照片，索引没有下载全册高清图。

执行项目要求的 `cd Cabinet` 后 `npm run verify`，覆盖类型检查、生产构建、性能预算、草稿泄漏、文档链接和关键路由 smoke test。新增自动检查优先覆盖内容关联、日期规则和返回行为，不编写复刻 CSS 实现的测试。

### 步骤 6：文档收口与发布判定

完成实现后才更新“当前实现”类文档，使其描述已验收事实；保留本文件的提案属性和实际执行记录，避免把计划误写为已完成。

确认 SCOPE 对本次相册发布的许可、页面生命周期及回归结果，再执行项目规定的发布流程。`npm run build` 通过不等于已发布；其他专题已获发布许可也不自动覆盖相册改造。

## 11. 设计负责人的验收结论标准

只有同时满足以下条件，才建议进入发布评审：

1. 用户能从封面认出某次约会或旅行，并立刻看到日期和地点。
2. 每册可独立保存从一张到多张照片，照片比例、色彩和顺序可信。
3. 索引、内页、大图层级清晰，返回、焦点、滚动及错误恢复可靠。
4. 手机、短屏与文字放大时仍能看照片、读说明、返回；无横向溢出。
5. 图片按实际浏览需要加载，装饰和大图不拖慢展柜与相册首屏。
6. 维护者通过新增资源和清单即可加入回忆，页面没有不可用的上传入口。
7. 内容字段及读取边界允许未来上传扩展，同时如实反映当前静态发布能力。
8. 页面符合全站材料、共享控件、代码规范与发布边界。
